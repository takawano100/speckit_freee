# freee 差分要求ワークベンチ

freeeの既存機能を起点に、「目標・人間・システム・データ」の4視点で差分要求を整理するローカルHTMLプロトタイプです。

## 起動

`open-local.cmd` をダブルクリックしてください。ローカルサーバーを必要な場合だけ起動し、ブラウザを開きます。

コマンドから起動する場合は、このディレクトリで次を実行します。

```powershell
python -m http.server 4173
```

ブラウザで `http://127.0.0.1:4173/` を開きます。

## 使い方

1. 左側からfreee既存機能または外部で作る候補を選ぶ
2. 「そのまま利用・追加・変更・外部補完・対象外・保留」から差分を選ぶ
3. 4視点の記述と未決定事項をレビューする
4. 人間が判断したものだけ「確定」にする
5. `Spec Kit入力` からMarkdownを出力する

## 要求変更PR

- 普段の編集は「PRなしの作業下書き」に保存され、確定ベースラインを上書きしない
- 変更理由を付けて「変更PR」を作成する
- レビュー時点ごとに「版を保存」する
- ベースラインとの差分を比較する
- 過去版へ戻しても、それまでの版と操作履歴は残る
- 合意した変更だけをマージして、新しい確定Revisionにする
- マージ済み・取り下げ済みPRも再オープンできる

入力内容はブラウザの `localStorage` に保存されます。freee APIは呼び出さず、freeeへの書き込みも行いません。

## 振り返り（現状ハブ）

ヘッダー中央のタブで、ワークベンチと「振り返り」を同じ画面内で切り替えます（ブラウザのタブは使いません）。

| タブ | 中身 |
|---|---|
| やったこと | 状態カード・実績ログ・出来ているファイル・残っていること |
| 組織図 ／ 従業員一覧 ／ 勤怠 | テスト事業所 12755401 に入れた組織・36人・8月の勤怠と給与 |
| 就業規則 | 今まで決めた規則（freeeに入れた／未設定／freeeに欄が無く外で持つ） |
| 勤怠の地図 | freee勤怠の口（打刻→日次→月次→承認→給与）と、勤怠だけでは出ないもの |
| わかったこと | APIの境界・時給者の社会保険・36協定・詰まった点 |

単体で開くときは `http://127.0.0.1:4173/fig_attendance_map.html`。`#rule` のようにタブ名を付けるとそのタブから開きます。
記事（note / Zenn）から参照するときは、このページと `REQUEST.md` を材料にします。

## 公開の仕組み（記事1本＝1プルリクエスト）

このフォルダは GitHub の公開リポジトリ `takawano100/speckit_freee` と同期しています。
やったことは随時コミットし、**note / Zenn の記事1本が公開できる単位でまとめて `main` に入れます。**

```powershell
# 1. 記事1本ぶんの作業ブランチを切る（記事番号と題材で名付ける）
git switch -c article/02-speckit-handoff

# 2. 作業のたびにコミット（小さくてよい）
git add -A
git commit -m "Spec Kit入力の出力例を追加"

# 3. 記事を公開するタイミングで PR を作り、そのまま取り込む
git push -u origin HEAD
gh pr create --fill
gh pr merge --squash --delete-branch
```

**1コミット目から守ること**：認証情報（トークン・client_secret・`.env`・`.claude.json`・`.mcp.json`）は `.gitignore` で除外済み。
freee の個人ユーザーIDは載せない。事業所 `12755401` と従業員IDは開発用テスト事業所の架空データなので、そのまま載せている。
コミットする前に `git status` で、意図しないファイルが増えていないかを見る。
