## Clarifications

### Session 2026-09-14

- Q: 「取得に失敗した朝」の赤い注意書きは、何を基準に「古い」と判定するか？ → A: 直近の営業日（前営業日）の打刻を含んでいなければ古い。週末・祝日は直前の営業日まででよい
- Q: 数字そのもの（読んだ結果）が開けなかったとき、画面には何を出すか？ → A: 一覧の枠は出し、全員の行を「取得できず」にする（空白を「残業なし」と誤読させない）
- Q: 所属長の一覧で、部下はどの順に並べるか？ → A: 状態の重い順（警告 → 注意 → 安全 → 打刻なし）、同じ状態なら残りが少ない順
- Q: 閾値（警告 45:00・注意 36:00）はどこで持ち、誰が変えるか？ → A: 正本は freee の36協定設定（年1回の協定更新で変わる）。こちらは写しを**有効開始日つき**で持ち、画面からは変えない。年度替わりで値が下がっても、進行中の期間の判定には**古い（その期間に有効だった）閾値**を使う。前日の閾値と最新の閾値が違うときは、対象期間の開始日に有効だった方を使う。**→ 要求の漏れとして `REQUEST.md` の台帳 #1 に戻し、要求本文（データ視点・決定 #12）を先に直した**

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 所属長が、部下の残業の「残り」と「超える日」を毎朝見る (Priority: P1)

所属長（部長）が朝、自分の部下だけの一覧を開く。部下ごとに、今月の時間外、45時間までの残り、
いまのペースで45時間に達する日付が見える。それを見て、その日のうちに仕事を減らす・振り分ける。

**Why this priority**: この機能の存在理由そのもの。freee の勤怠モニターは「超えたあと」に
アイコンを出すだけで、「超える前」を誰にも知らせない（T07 で実測済み）。

**Independent Test**: テストデータ `data/saburoku_2026-09.json` の人事部・経理部・財務部・
労務部を開き、T02・T03・T04・T07 の期待値（残り・状態・予定日）が出れば、それだけで価値がある。

**Acceptance Scenarios**:

1. **Given** 三上（労務部）の9営業日の時間外が 24:45（1日 2:45）のとき、**When** 労務部長が一覧を開く、
   **Then** 三上は「安全」で、残り 20:15、超える予定日 9/28（月）、月末見込み 52:15 が出る（T07）
2. **Given** 岡田（経理部）が 30:45 のとき、**When** 経理部長が開く、**Then** 岡田は「安全」（注意の線 36:00 未満）だが残り 14:15、超える予定日 9/18（金）、月末見込み 64:55 が出る（T03。9/14 の閾値決定で状態は「注意」→「安全」に読み替え）
3. **Given** 白石（財務部）が 45:45 のとき、**When** 財務部長が開く、**Then** 白石は「警告」で「超過 0:45」「到達済み」（T04）
4. **Given** 堀内（人事部）が 18:00・加瀬が 7:30 のとき、**When** 人事部長が開く、**Then** 2人とも「安全」で予定日は「月内は超えない見込み」。並びは残りが少ない順：堀内（23:00・残り 22:00）→ 長瀬（8:30・残り 36:30）→ 加瀬（7:30・残り 37:30）→ 打刻なしの相川（T02。9/16 実装時に数字を現データに合わせて修正）
5. **Given** 人事部長が開く、**When** 一覧を見る、**Then** 出るのは人事部の主務の部下（長瀬・堀内・加瀬）と自分だけで、他部署の人は出ない（T14・T16）
6. **Given** 相川は人事部長であり労務部課長を兼務している、**When** 労務部長が開く、**Then** 相川は労務部の一覧に出ない（主務の所属長が見る。T14）

### User Story 2 - 打刻の状態を見分けて、数字の信用度が分かる (Priority: P2)

所属長は、部下の数字が「打刻に基づく数字」か「打刻していないだけ」かを見分ける。
打刻していない日は残業に積まず、「打刻なし n日」として出す。欠勤や退勤忘れは打刻なしと区別する。

**Why this priority**: 打刻が無い日、freee は所定どおり480分を立てる（みなし）。これを残業に
積むと数字が壊れ、積まないと「打刻していない」事実が消える。両方見せないと所属長が誤る（T05・T06・T12）。

**Independent Test**: 長瀬（9日中5日打刻・3日なし・1日退勤なし）・加瀬（9/8 欠勤）・
堀内（9/12 土曜出勤）・平井（9日とも残業ゼロ）で、T01・T05・T06・T10・T11・T12 の期待値が出る。

**Acceptance Scenarios**:

1. **Given** 相川は今月1日も打刻していない、**When** 一覧を見る、**Then** 状態は「打刻なし」、数字は「—」、打刻なし 9日/9日（T05）
2. **Given** 長瀬は5日打刻・3日打刻なし・1日は出勤打刻だけ、**When** 見る、**Then** 時間外は打刻した5日ぶん（8:30）、
   「打刻なし 4日/9日（退勤なし 1）」、1日あたりは5日で割った値（T06・T12）
3. **Given** 平井は9日とも 9:00–18:00 で打刻、**When** 見る、**Then** 「安全 0:00」と出て、打刻なしの人と区別できる（T01）
4. **Given** 加瀬の 9/8 は欠勤、**When** 見る、**Then** その日は「欠」と出て、打刻なしには数えない（T11）
5. **Given** 堀内が 9/12（土・所定休日）に5時間働いた、**When** 見る、**Then** 5時間は今月の時間外の合計に含まれ、
   「休日出勤 1日」と出る。1日あたりのペースには含めない（T10・T27）

### User Story 3 - 労務担当が全社を状態順に見る (Priority: P3)

労務担当は、全部門・全員を「警告 → 注意 → 安全 → 打刻なし」の順で見る。部門・所属長・兼務・
データの取得状態で識別でき、所属長がいない部署や所属長が見ていない場合の押さえになる。

**Why this priority**: 主役は所属長だが、所属長が見ていないときに誰も気づかない、を防ぐ（T17・T15）。

**Independent Test**: 全社ビューを開き、34人（役員2人を除く）が状態順に並び、件数（警告1・注意1…）と
部門ごとの要対応数が出れば足りる。

**Acceptance Scenarios**:

1. **Given** テストデータの34人、**When** 労務担当が全社を開く、**Then** 警告・注意・安全・打刻なしの人数が出て、
   一覧は警告→注意→安全→打刻なしの順（T17）
2. **Given** 部長が自分の部署の行を見る、**When** 所属長の列を見る、**Then** 「自分（部長）」と出る（T13）
3. **Given** 状態や部門で絞る、**When** フィルタを変える、**Then** 一覧と件数が絞られる（T17）
4. **Given** 部長のいない部署がある、**When** 全社を開く、**Then** その部署は「所属長なし」と印が付く（T15・保留）

### User Story 4 - 数字の鮮度が分かる（取得に失敗した朝） (Priority: P3)

毎朝、前日までの数字が出ている。取得に失敗した朝は、古い数字を黙って出さず、
「前回 ○月○日 ○時の数字です」と目立つ形で出す。

**Why this priority**: 「翌朝までに数字が出ていること」だけが時間の要件。出ていないことが
分からないのが一番危ない（T25）。

**Independent Test**: 「今日」を 9/15 に置いたテストデータ（打刻は 9/11 まで）で開き、赤い注意書きが出る。「今日」を 9/14 にすると出ない。

**Acceptance Scenarios**:

1. **Given** 今日が 9/15（火）で、数字が 9/12（土・堀内の休日出勤）の打刻までしか含んでいない（前営業日 9/14 が無い）、**When** 開く、**Then** 画面の上に「前回 9/13 19:00 の数字です（9/12 の打刻まで）」が赤で出る（T25。実装時に最終打刻が 9/12 と分かり修正）
2. **Given** 今日が 9/14（月）で、数字が 9/11（金）の打刻まで含んでいる（前営業日＝9/11）、**When** 開く、**Then** 注意書きは出ず、取得日時が下に小さく出る
3. **Given** 今日が 9/13（日）、**When** 開く、**Then** 直前の営業日 9/11 まで含んでいれば古くない

### Edge Cases

- 月初1〜2日：打刻した日が1日しか無く、ペースが1日ぶんで決まって予定日が大きく揺れる（T24・未）。
  表示は壊れないこと。予定日は出すが、打刻日数が3日未満なら「まだ目安」と添える（Assumptions 参照）
- 45時間を超えたあとも増える（60h・100h接近）：「超過 n:nn」で表示し、バーは100%で止まる（T08・未）
- 深夜が混ざる：時間外に含める。深夜を別に出すかは今回決めない（T09）
- 法定休日（日曜）の出勤：freee の返し方が未確認（T28・未）。所定休日と同じ扱いで表示し、記録する
- 部長本人に残業がある：「自分」の行が注意・警告になる。誰が気づくかは決定どおり本人（T29・未）
- 有給・半休：freee で付与が無いと入れられないため未確認（T11・保留）。欠勤と同じく「打刻なし」に数えない前提
- 年度替わり（36協定の更新で閾値が変わった月）：新旧の閾値が併存する。対象月の開始日に有効だった閾値で判定し、画面に「閾値 45:00（2026-04-01〜）」のように出す。翌月から新しい閾値に切り替わる（T30・未）
- 取得できた人と できなかった人が混ざる朝：できなかった人の行に「取得できず」を出す（T25 の派生）
- 数字そのものが開けない朝：一覧の枠は出し、**全員の行を「取得できず」**にする。数字の欄は空にせず「取得できず」と書く。空白の画面を「全員残業なし」と誤読させない（T25 の派生・FR-012）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 所属長が開いたとき、**主務の所属がその所属長の部署である従業員**（部長自身を含む）だけを出す。
  兼務先の部下は出さない。課長は部長の一覧に出る。並びは**状態の重い順**（警告 → 注意 → 安全 → 打刻なし）、同じ状態なら残りが少ない順。（T13・T14・T16）
- **FR-002**: 期間は**勤務月**（1日〜末日）で数える。支払月では数えない。（T03・T04）
- **FR-003**: 従業員ごとに、当月の**所定日で打刻のあった日**の時間外を合計する。打刻の無い日（みなし）は合計に入れない。（T05・T06）
- **FR-004**: **所定休日・法定休日に打刻のあった日**の時間外は合計に入れる。ただし「1日あたり」の計算には入れない。（T10・T27）
- **FR-005**: 従業員ごとに、残り（警告閾値 − 合計）、1日あたり（合計 ÷ 打刻した所定日数）、
  超える予定日（1日あたりを残り営業日に順に足して警告閾値に届く日）、月末の見込み（合計 ＋ 1日あたり × 残り営業日）を出す。（T03・T07）
- **FR-006**: 状態を4つに分ける。**警告**＝合計が警告閾値（初期値 45:00）以上、**注意**＝注意閾値（初期値 36:00）以上 警告閾値未満、
  **安全**＝打刻があり注意閾値未満、**打刻なし**＝当月に打刻が1日も無い。（T01〜T05）
- **FR-006a**: 閾値の**正本は freee の36協定設定**（年1回の協定更新で変わる）。こちらは写しを**有効開始日つきの履歴**として設定ファイルで持ち、
  画面からは変えない。更新は freee 側を変えたときに手で行う（freee の36協定設定は API で読めないことを実測済み）。（決定6）
- **FR-006b**: 判定に使う閾値は、**対象期間（勤務月）の開始日に有効だった閾値**とする。年度替わりで閾値が下がっても、進行中の月の判定は
  古い閾値のまま。前日の閾値と最新の閾値が違うときは、新しい方を黙って使わない。画面には使っている閾値と有効開始日を出す。（T30）
  ※ 注意の線は 9/14 の決定により 36h（45h × 80%）。テスト台帳の T03（岡田 30:45）はこの閾値では「安全」になるため、
  期待値を「安全・予定日 9/18」に読み替える。台帳の更新は実装の検証時に行う。
- **FR-007**: 打刻なし日数（所定日のうち打刻が無く欠勤でもない日）、欠勤日数、退勤打刻の無い日数、休日出勤日数を、
  従業員ごとに別々に出す。（T05・T06・T10・T11・T12）
- **FR-008**: 出勤打刻だけで退勤打刻の無い日を「退勤なし」として見分ける。日次勤怠の記録だけでは打刻なしと区別できないため、
  打刻そのものの記録を併せて読む。（T12）
- **FR-009**: 欠勤の日は「欠」と出し、打刻なしに数えない。（T11）
- **FR-010**: 労務担当は全従業員（勤怠管理の対象外である役員を除く）を、警告→注意→安全→打刻なしの順で見られる。
  状態ごとの人数、部門ごとの要対応数、部門・状態での絞り込みを持つ。（T17）
- **FR-011**: 全社の一覧では、各従業員の部門・本部・所属長・役職・兼務の有無・データの取得状態を出す。
  部長自身は「自分（部長）」、部長のいない部署は「所属長なし」と出す。（T13・T15）
- **FR-012**: 数字の取得日時を画面に出す。数字が**直近の営業日（前営業日）の打刻を含んでいない**ときは「古い」とみなし、画面の上部に
  「前回 ○月○日 ○時の数字です（○/○ の打刻まで）」を目立つ色で出す。週末・祝日は直前の営業日まで含んでいれば古くない。古い数字を黙って出さない。数字そのものが読めないときは一覧の枠を出し、全員の行を「取得できず」にする。（T25）
- **FR-013**: 営業日（所定日）は freee の勤務カレンダーから決める。祝日・所定休日・法定休日をこちらで持たない。カレンダーは**前月末の営業日から対象月末まで**を読む（月初の朝の鮮度判定に前営業日が要る。漏れ台帳 #2）。カレンダーに前営業日が無いときは「前営業日を判定できない」と出す。（T10・T31）
- **FR-014**: freee からは**読むだけ**。この機能から freee へ書き込まない。（憲法 I）
- **FR-015**: 通知（メール・チャット等）は出さない。見る手段は画面だけ。（決定5）
- **FR-016**: 日別の表を出す。所定日ごとに時間外、打刻なしは「未」、欠勤は「欠」、退勤打刻なしは「退勤なし」、
  休日出勤の日は列を足して示す。（T06・T10〜T12）

### Key Entities

- **従業員**: freee の従業員。社員番号・氏名・役職・雇用形態。役員は対象外。主務の所属と兼務の所属を持つ
- **所属**: 部署（本部の下の部）と、その部署の所属長（役職が部長の人）。freee の所属・役職から毎回導き、こちらで表を持たない
- **勤務カレンダー**: 日付ごとの区分（所定日／所定休日／法定休日）。freee から読む
- **日次勤怠**: 従業員×日付。出勤・退勤・休憩、時間外・深夜（freee が計算）、欠勤、みなしか否か。freee から読む
- **打刻**: 従業員×日付×種類（出勤・退勤・休憩）。退勤なしの判定に使う。freee から読む
- **閾値**: 警告（初期値 45:00）・注意（初期値 36:00＝45:00 × 80%）と**有効開始日**。正本は freee の36協定設定で、こちらは有効開始日つきの履歴として写す。判定には対象月の開始日に有効だった値を使う
- **月次の断面（従業員ごと）**: 合計・残り・1日あたり・予定日・月末見込み・状態・打刻なし日数・欠勤日数・退勤なし日数・休日出勤日数。毎朝計算し直す
- **取得の記録**: いつ・何人ぶん読めたか／読めなかったか。鮮度の表示に使う

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 所属長は一覧を開いてから **1分以内**に、自分の部下のうち「今月45時間を超える見込みの人」を言える（T07）
- **SC-002**: `TESTCASES.md` の **T01〜T07・T09〜T17 の期待値がすべて画面で確認できる**（済のケースを実装で再現）
- **SC-003**: 45時間を超える見込みの人が、**超える前に**（予定日より前の営業日に）一覧に予定日つきで出る。テストデータでは三上（9/28）・岡田（9/18）
- **SC-004**: 打刻していない人・退勤を忘れた人が、残業ゼロの人と**見分けられる**（T01 と T05・T12 が同じ画面で区別できる）
- **SC-005**: 取得に失敗した朝は、開いた人が**古い数字だと気づく**（T25。注意書きが最上部に出る）
- **SC-006**: 労務担当は全社を開いて **1分以内**に、警告・注意の人数と、その人がどの部門・どの所属長の下かを言える（T17）
- **SC-007**: 要求（REQUEST.md 第2部）に無い機能を含まない。範囲外の10項目が画面に無い

## Assumptions

- 見る人の認証・権限・配信の形（どこで動かすか、freee のログインに乗せるか、見た記録を残すか）は要求で**未決**。
  この仕様の範囲では、部署を選んで所属長の立場で見る／全社を労務担当の立場で見る、の切替で代える。本番の形は別の仕様にする
- 本人（部下）に自分の残り時間を見せるかは**未決**。この仕様では所属長と労務担当だけが見る
- 数字は毎朝、前日までの日次勤怠を読んだものとする。読む手段（手動・自動）はこの仕様で決めない。テストデータは読んだ結果の形（JSON）で用意する
- 1日あたりのペースは、打刻した所定日が1日でもあれば出す。3日未満のときは「まだ目安」と添える（T24 の暫定対応）
- 深夜の時間外は合計に含め、別には出さない（T09）
- 法定休日の出勤は、所定休日と同じ扱いで合計に含める。freee の返し方が確認できたら見直す（T28）
- 有給・半休は欠勤と同じく「打刻なし」に数えない。ただし freee で付与が無く未確認（T11）
- 対象は freee 開発用テスト事業所 12755401 の架空データのみ。従業員34人（役員2人を除く）、15部門、全部署に部長がいる
- フレックス・パートの従業員はテストデータに含まれるが、この仕様では他と同じ計算をする。正しい扱いは範囲外（T19・T20）
- 性能の要求は無い

## Out of Scope

- 複数月平均（80h）・年間（360h／720h）・特別条項（年6回）の追跡
- 残業の事前申請・承認、承認経路
- 打刻の入力画面、給与計算、勤怠の締め
- 36協定の書面・届出・限度時間そのものの管理
- 通知（メール・Slack・LINE）
- フレックスタイム制・パートの正しい時間外計算、役員
- 認証・権限・配信・監査（本番の形）
